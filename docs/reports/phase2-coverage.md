## 4. 기준값 조정안

1. **눈치게임 — 이력 2주가 찰 때까지(10-26) 예측창 대리값을 쓰지 않는다 (적용함, 2026-10-12).**
   - 근거: 10-17(토) 추천 77건 중 눈치게임 55건이고, 그중 46건은 인기도가 없다. 이번 토요일 예측이 같은 30일 창의 다른 토요일보다 낮다는 뜻일 뿐이라 "평소보다 한산"이라고 말하기 어렵다.
   - 방법: 설정 `usualCongestion.forecastFallback: false`. 10-26부터는 이력 기준(임시)으로 자동 판정된다.
2. **시간대 공략 비율 0.5 — 유지, 10-26에 재평가.** 서울 실측 패턴이 생긴 뒤 통과 수를 보고, 하루 3곳 미만이면 0.6을 검토한다.
3. **나머지 기준값(인기도 70, 혼잡 40·60, 추세 +100%, 장기 −30%, 한산 가능성 40·60) — 유지.** 설계 시뮬레이션과 현재 분포 모두 하루 추천 수가 피드(유형별 10곳)를 채우는 범위다.
4. **인기도 가중치 0.6 : 0.4(D-2) — 유지.** 검색·블로그 백분위 상관 0.53(설계 시뮬레이션), 두 신호가 겹치지 않는다.
5. **대표 유형 순서(D-3) — 유지:** 눈치게임 → 적당한 핫플 → 시간대 공략 → 숨은 클래식 → 얼리 핫플.

## 5. 대상 장소 수 확정안

- **확정안: 장소 목록의 노출 장소 전체(현재 3,713곳)를 대상으로 한다.** 모두 혼잡 예측이 있고, 네이버 하루 상한(블로그 2,000 · 트렌드 800) 안에서 하루 약 531곳씩 주 1회 갱신된다.
- 유형 품질 표시: 인기도·평소 혼잡이 없는 장소는 해당 유형에서 빠진다(FR-SCORE-10). 시·도별: 서울 558, 경기 1,053, 강원 714, 충남 603, 충북 400, 인천 256, 대전 98, 세종 31.

## 7. 설계와 다르게 구현한 것

- **시간대 패턴의 '요일별' 단계를 두지 않았다.** 평일·휴일 두 가지만 있다. 8주가 차기 전에는 요일별 표본이 너무 적어서다. 4주 차에 재검토한다.
- **날짜별 전체 장소 점수 파일(`data/scores/daily/`)을 만들지 않았다.** 하루 약 10MB씩 저장소가 커져서다. 날짜별 혼잡 예측은 `data/latest/cnctr.json` 에 있고, 추천 파일에는 유형에 해당한 장소만 담는다.
- 분류 표준이 아직 없어 경기 패턴만 있는 장소는 `gg_only` 로 표시하고, 시간대 공략 판정에서 뺀다.

## 8. 남은 문제

- 장기 관심 변화의 창이 백필 시점(2026-10)에 고정된다. 분기마다 다시 백필할지 결정해야 한다(수집기 수정).
- 공휴일 자료가 앞으로의 달만 쌓인다. 과거 공휴일은 이력 판정에서 평일로 다뤄질 수 있다(10-12 이후 이력에는 영향 없음).
- 집중률 관광지 12곳은 30일 내내 값이 거의 같다. 보고만 하고 판정에서 빼지는 않는다.
